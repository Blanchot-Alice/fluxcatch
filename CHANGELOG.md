# Changelog

## 0.2.5 — Unreleased

- Removed the "authorized, but Chrome's bridge is not ready" dead end. Chrome binds `chrome.runtime.connectNative` only into a service worker that starts after the optional permission is granted, so the worker that was alive during the grant could never connect. The worker now snapshots its session state, reloads the extension once (five-minute cooldown, never a loop), replays the snapshot in the replacement worker, reopens the settings page, popup or downloads page that asked, continues the download that was clicked, and posts one notification saying so. The measured wait/"restart Chrome" guidance remains only as the fallback for a binding that a reload does not fix.
- Redesigned every surface in the spirit of Monet (`DESIGN.md` records the translation and the token decisions). Shared tokens are a two-hour palette — Morning (primed cream `#F4F0E9` ground, deep indigo-violet `#2B2E4A` text) and Dusk (dusk pond `#1C2140` ground, warm pearl text) — with hues chosen by state rather than brand: pond for action, lilac for hover and paused, celadon for complete, ochre for warnings, vermilion only for errors, harbour for queued. No pure black or white anywhere; shadows are violet; separation is tonal or a translucent indigo line. The ground is a procedural atmosphere (`extension/ui/atmosphere.css`: three slowly drifting radial light fields plus an SVG feTurbulence canvas weave, no raster assets); lists are continuous surfaces with a tonal zebra instead of cards with hairlines; progress bars reveal a lilac → pond → ochre gradient that warms as they fill, cross-fade to celadon on completion and ripple once; live rows gain a speed graph with a blurred reflection and, for streams reporting "分片 n/m", a low-contrast segment map (`extension/ui/speed-graph.js`). Titles are set in Fraunces at book weight (soft axis off) and UI text in IBM Plex Sans at 94% width with a 400/500 weight hierarchy, both bundled under `extension/ui/fonts/` with their OFL licences so nothing is fetched. A component preview with both themes side by side plus density and reduced-motion toggles lives at `preview/preview.html`; `scripts/contrast_report.mjs` checks every text/surface pair in both themes (all ≥ 4.5:1, control boundaries ≥ 3:1) and writes the table into `DESIGN.md`. The popup's empty Jobs tab shows one serif line and nothing else; the engine card and the notification hint return only once a job exists. The mark and icons are now a lily pad, ripple and blossom on a cream disc, and the designer's defaults follow (accent `#3E6E92`, radius 14, text on a custom accent is cream or indigo rather than white or black). `tools/live/shots.mjs` renders every surface and the preview in light and dark mode for visual review, and waits for Chrome to release its profile between its two sessions.
- Pause and resume. A running native job can be paused from the popup, the Side Panel and the downloads page; the engine keeps the direct-download part file with its validated checkpoint, or the whole staged HLS/DASH segments plus a small pause marker (`<name>.part.json`, schema 3: work-directory name and a URL digest, never the URL), and a later job that asks for the same output name picks everything up where it stopped. Chrome's own downloads pause and resume through `chrome.downloads`. The worker keeps a resume recipe per job (tab, media-key digest, options, the engine's final file name) in session storage, so resuming survives worker restarts while the page is still open; cancelling a paused job asks the engine to discard its leftovers, and markers older than a week are collected at startup like stale `.part` files.
- A download queue. Settings gained "同时进行的下载数" (1–6, default 3); every native job carries it and the engine admits that many transfers at once, telling Chrome when a job is waiting in line. Reported queued jobs show the engine's own "排队中" message.
- Batch and link downloads. "全部下载" in the popup (for the current filter) and the Side Panel starts every visible card with the page's default settings through one worker call that reports how many started; a link icon in the popup, "链接下载" in the Side Panel and "新建下载" on the downloads page accept a pasted media address. The worker learns the type from the extension (or a HEAD/one-byte probe without credentials), registers the address as an ordinary `user_supplied` candidate of the current tab, and downloads it on the normal path, so retry, resume and the card all work.
- A chosen save location. Settings → 基础下载 → "更改位置…" asks the engine to show the native macOS folder picker; the choice is kept in the engine's own config file (`~/Library/Application Support/FluxCatch/config.json`), earlier folders stay openable through the confined Finder actions, and "恢复默认" returns to `~/Downloads/FluxCatch`. `FLUXCATCH_DOWNLOAD_DIR` still wins for tests and harnesses.
- Keyboard shortcuts: ⌥⇧F opens the popup, ⌥⇧D the downloads page, ⌥⇧W the Side Panel workspace (all editable at chrome://extensions/shortcuts).
- Added a durable download history: finished, failed and cancelled jobs are kept in extension-private storage across popup closes, worker suspensions, browser restarts and extension reloads, with the file size, duration, resolution, codecs, source page and a small poster frame for each saved file. The popup's job list and the Side Panel now show the newest finished file first with "打开" / "在 Finder 中显示" / "重试" / "来源页面" actions, and a new full-page 下载记录 (downloads/downloads.html) lists everything grouped by day with search, status filters, 移到废纸篓 and a live view of running jobs. Files the local engine saves never appeared in chrome://downloads; this page is their record.
- The native engine gained Finder-facing file actions (`reveal`, `open`, `open_folder`, `trash`, `stat`) that are confined to its own download folder (symlinks, traversal, unfinished `.part` files and anything outside the folder fail closed), reports its download folder in `pong`, and enriches `complete` with the published path, size, ffprobe media facts, a poster frame and elapsed time. The popup/Side Panel/Settings "download folder" buttons open that folder through the engine instead of Chrome's default download directory.
- Completion notifications are on by default (the optional browser permission is requested from an explicit "开启通知" card, never silently), carry "在 Finder 中显示" / "打开" buttons, and clicking the notification reveals the file; failed-job notifications offer "重试". The toolbar badge turns pool-green and its tooltip reports the running jobs and overall percent while anything downloads.
- Fixed the DOMParser-free DASH manifest parser that the MV3 service worker actually runs: its regular expression swallowed every self-closing `<Representation …/>` up to the next closing tag, so a template-based MPD (Akamai's Big Buck Bunny ladder, most dash.js sites) exposed a single quality instead of its whole ladder, lost the inherited AdaptationSet `mimeType`/`codecs` and never reported `mediaPresentationDuration`. It now walks the tag stream with an element stack, resolves nested MPD/Period/AdaptationSet/Representation `BaseURL`s in document order and keeps `Representation` indices aligned with the native planner's.
- DASH manifests now get the same automatic one-shot inspection as HLS playlists (and a user probe records it too), so an MPD card shows its real runtime and best height right away and the player's numbered segment files fold away instead of appearing as separate 1 MB "videos" beside it.
- Output integrity: a single-stream transfer now fails when the body ends before the probed length or the server answers with anything but 200, a reserved output name that became occupied is published under the next free name instead of failing the whole job, stale `.part` / checkpoint / staging leftovers older than a week are collected at startup, and FFmpeg phases report `remuxing` with a real 0–100% (sourced from ffprobe) instead of resetting a finished transfer's bar to 0%.

- Detected pages now present their full picture immediately: every observed HLS playlist gets its bounded inspection right away (the old "wait for a second rendition" gate left single-playlist sites — most of them — without any card metadata), a parsed media playlist with real runtime counts as the page's ladder and folds same-site direct MP4s (hover previews included) away, the MSE player's own videoHeight/duration is replayed onto cards whose playlist carries no resolution, and the surviving ladder card is marked 推荐.
- Made system-proxy discovery live: the native engine re-reads the OS proxy configuration with a five-second cache instead of capturing it once at startup, so toggling a proxy, switching profiles, or turning it off takes effect within seconds — going abroad and disabling the proxy needs no Chrome restart, and bilibili-style domestic CDNs keep working whenever the proxy's own routing sends them direct.
- Survived hostile networks during HLS transfers: connection-level failures (proxies and CDNs cutting TLS mid-burst, measured ~4.5% of requests in the field) now ride out a widened retry window — six attempts with 0.5→8s backoff for segments, manifests and keys instead of four attempts inside ~2.5 seconds, which let one burst kill a whole job.
- Thumbnail policy accepts sibling CDNs of the same registrable domain (assets-cdn.example.tv for example.tv), so sites serving their own posters from a CDN subdomain show covers again; exact-origin matching rejected exactly those.
- Added native-backed HLS playlist inspection: when a hotlink CDN refuses the extension's own probe fetch, the pinned native engine replays the page's observed headers to read the playlist (same policy gates, no private-network side door), so cards on such sites regain duration, rendition height and the quality dropdown; AES-128 HLS downloads now work end to end (raw segments and 16-byte keys stage through the pinned client, FFmpeg's local HLS demuxer decrypts against a rewritten local playlist, only DRM/SAMPLE-AES stays metadata-only), and page-referenced thumbnails render on cards again under the existing origin-allowlist policy.
- Grouped masterless rendition families without requiring a probe: per-quality media playlists sharing one directory and the site's own rendition naming (`720P_…` / `1080P_…`) collapse into one card with a working quality dropdown even when the CDN refuses every extension probe fetch (heights then come from the rendition filenames), while bare directories with different-object masters (Wistia-style) and query-tokenized asset twins stay ungrouped.
- Collapsed each page to one playable video card: sub-five-second hover-preview loops never list, and once a ladder card is probed (HLS master, DASH manifest, or DASH pair) same-CDN metadata-only MP4s and standalone media playlists fold away so the quality dropdown is the single entry point; suppression is recomputed on every read so worker restarts cannot resurrect hidden rows.
- Refused HTML pages answered in place of media: every direct/pair transfer now rejects `text/html`/XHTML responses (or an untyped body that sniffed as HTML) with a clear 刷新重试 error instead of silently saving an unopenable page as the media file, leaving no partial output behind; the extension likewise never accepts a candidate whose URL is the page itself (the embed-fallback/pre-MSE shape that produced HTML "videos" on hotlink-protected CDNs).
- Gated generic stream aggregation behind whole-object evidence: a track only aggregates when its request carried a `Range` header or its response a `Content-Range` total, so segment-template players (thousands of numbered plain-GET files) can never pose as renditions or fill the quality dropdown with few-second clips.
- Promoted opaque `application/octet-stream` objects by strong inference only: beside a declared audio track and with no declared video track they become the document's video track (the whole-object shape several DASH sites serve); every other configuration — including octet-stream-only documents — fails closed instead of guessing by size.
- Aligned DASH manifests with the HLS quality flow: `.mpd` probes now expose their representation ladder to the download dialog's dropdown through the same opaque selectors, and the native planner receives the chosen representation as a preferred object URL that must match exactly or fail loudly (default remains best-by-resolution).
- Added generic MSE stream aggregation: large whole-object `m4s`/`cmfv`/`cmfa` responses with declared video/audio MIME types are paired per browser document into one downloadable video+audio card on any site, using only runtime signals (same document, complementary MIME, ≥1 MB object size) instead of site naming contracts, so player redesigns and new CDN segment ids cannot blind detection.
- Generic cards expose every rendition the player streamed in the download dialog's quality dropdown (ranked by object size with readable labels, defaulting to what the user watches), so any site's video can be saved at a chosen quality just like Bilibili cards; audio-only extraction and container conversion apply to them as well.
- Opening a Bilibili video page now paints the badge with the downloadable count immediately via one cookie-scoped, cooldown-limited playurl lookup; a later playback request is merged by the success TTL instead of re-querying, and the full logged-in ladder (up to 4K) is present before the first segment request.
- Raised the default parallel Range worker count from 8 to 12 for direct, DASH-pair and HLS transfers (still user-tunable 1–24 in Settings) so large 4K objects saturate more of the CDN's per-connection limits.
- Accepted Bilibili's 2026-08 HEVC object naming (`{cid}_da2x1-1-1001xx.m4s`) alongside the classic `30[0-2]xx` ladder, normalized the `_da2`/`_da2x1` codec-stream infix out of asset-family pairing, and restored cid extraction from the new object names; measured 100109/100110 map to 360p/480p while the API leg fills in the rest.
- Generic aggregated pairs keep their track URLs worker-private like Bilibili pairs, replay the page's own Referer on download instead of any site-specific header, and expire two minutes after the last observation.
- Fixed Bilibili CDN probing when a server rejects `HEAD` but accepts a one-byte Range `GET`; HTTP error responses now retain connected-peer validation before the safe fallback runs.
- Stopped Instagram `bytestart`/`byteend` MediaSource fragments from appearing as dozens of standalone MP4 downloads that QuickTime cannot open.
- Added bounded top-frame Instagram/X SPA response observers that publish only strictly allowlisted complete MP4 metadata; Instagram keeps one best rendition and X prefers the highest-bitrate progressive variant.
- Routed those allowlisted Instagram/X progressive MP4 transfers through Chrome by default so they reuse the browser's working network path when the native process is reset or times out on Meta/Twitter CDNs; **可信直链也使用本地下载引擎** opts the exception back into Native, and the save-location prompt applies only to Chrome-backed saves.
- Made the site observers SPA-aware, replaced stale/recommended Instagram rows with the current shortcode-bound rendition, preserved X source lineage after webRequest merging, and added a bounded page-scoped cache that restores signed candidates after MV3 worker suspension without writing them to extension storage.
- Added pinned-client download and local FFmpeg merging for clear static HLS masters with separate audio renditions, including audio-only extraction without downloading video segments.
- Added shared, packaged UI tokens and control primitives for Settings, popup, and Side Panel while retaining vanilla Manifest V3 HTML, CSS, and JavaScript.
- Reorganized Settings around runtime identity, basic downloads, performance, detection and naming, privacy and network boundaries, local capabilities, notifications, and non-interactive Lab roadmap states.
- Added normalized dirty-state tracking, field-level validation and an error summary for concurrency, minimum size, filename templates, and ignored domains; failed saves retain the unsaved state.
- Moved optional notification and Native Messaging permission requests to their originating user gestures and added an explicit confirmation step before enabling private-network media access.
- Separated native-host connection, protocol compatibility, FFmpeg installation/local processing, yt-dlp installation, external-tool networking, and build availability so installed tools are not presented as enabled features.
- Unified restrained pending, success, failure, toast, focus-restoration, and duplicate-action protection across the popup and Side Panel, including card-local manifest loading feedback.

## 0.2.4 — 2026-08-23

- Split network guarantees by execution layer: the extension validates literal URL/host information, purpose, provenance, and worker-derived origins; the native client validates DNS answers, pins connected peers, reauthorizes redirects and manifest children, and defends against rebinding.
- Replaced crash-resume URLs with version-2 checkpoints containing only SHA-256 digests of the URL and entity validators, plus length and completed byte ranges; legacy checkpoints are discarded.
- Replaced executable-looking public candidate URLs with `displayUrl`, redaction/copyability flags, and opaque `{id, kind, generation}` references; real targets and headers remain worker-private.
- Added build channel, commit, timestamp, protocol, capability-profile diagnostics, and fail-closed extension/native compatibility checks.
- Kept passive detection as the default: Bilibili quality enrichment now runs only after the popup or Side Panel opens, a manual rescan, or the off-by-default automatic-enrichment setting.
- Removed the unsupported Bilibili bangumi matcher and bounded/batched content-script payload scanning.
- Removed stable YouTube, yt-dlp, and live-HLS controls; unavailable capabilities now appear only in the build capability matrix.
- Disabled page-derived remote-thumbnail fetching in the stable profile; Popup and Side Panel retain packaged media-type fallback tiles.
- Made the current HLS boundary explicit in code and UI: only clear static VOD is downloadable in 0.2.4; live, AES-128/SAMPLE-AES, discontinuity, and separate-audio playlists fail closed.
- Resolved HLS and DASH relative resources from final redirected manifest URLs and made credential removal monotonic across redirect chains.
- Hardened CI checkout and action pinning, added bounded test/package evidence summaries, and kept native tests, Python compilation, validation, and Chrome for Testing E2E mandatory.
